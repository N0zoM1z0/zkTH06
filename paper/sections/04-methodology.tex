\section{Methodology}

\subsection{Fail-closed replay ingestion}

The replay loader owns the decoded buffer and rejects invalid magic, version,
checksum, character/shot metadata, difficulty, unaligned or non-monotonic stage
offsets, malformed block sizes, unsupported input bits, regressing frame
numbers, and missing or malformed playback sentinels.  Playback cursors are
bounded by the first validated sentinel rather than by ambient process memory.

\subsection{Authentic frame order}

Replay input is injected by the existing replay callback at calculation
priority 5, after the game manager and before Stage, Player, Enemy/ECL,
Effects, Bullets/Items, and GUI.  Dialogue can restart the calculation chain;
this behavior is retained.  Complete Shoot, Bomb, Focus, Skip, and direction
masks are replayed.  Compatibility mode follows deaths, bombs, and respawns
instead of applying the reinforcement-learning harness's first-hit terminal.

\subsection{Two-level canonical tracing}

Writing every field of hundreds of entity slots on every frame would generate
multi-gigabyte traces.  The differential design therefore has two levels:

\begin{enumerate}
  \item a fixed-size per-frame record containing metadata and cryptographic
  digests for ordered subsystems; and
  \item a field-level canonical snapshot for a selected tick around the first
  digest mismatch.
\end{enumerate}

Every serializer uses explicit little-endian integer widths, raw IEEE-754 bit
patterns, stable array slot indices, and offsets relative to loaded script
bases.  It never hashes pointers, compiler padding, locale-dependent text, or
unordered container iteration.  Subsystem separation distinguishes global/RNG,
Player, player bullets, Enemy/ECL, enemy bullets, lasers, items, Stage,
GUI/message, and Effects; owner-local ANM cursors will be embedded in the
subsystem whose future transition they affect.

Named C++ members are not automatically semantic state.  A member is admitted
only when it is initialized and future-live under the current control mode.
For example, ANM interpolation endpoints and timers are serialized only while
the corresponding interpolation duration is active.  Conversely, an inactive
allocation slot cannot be omitted merely because its active flag is clear: a
reuse proof must show that every residual value is overwritten before read.

\subsection{Differential loop}

For each pinned replay, both runners must use the same data hashes and replay
bytes.  The comparison proceeds in frame order, first comparing the root digest,
then subsystem digests, then a rerun with the field-level snapshot at the first
failing tick.  A final score match is supporting evidence but never substitutes
for frame equivalence.

\subsection{Refinement and arithmetic soundness}

A zkVM proof is sound only relative to the transition function implemented by
its guest.  We therefore separate three obligations: proof-system soundness for
the guest, equivalence between the guest and the frozen canonical transition,
and fidelity between that transition and the shipped executable.  Success on
one obligation does not silently discharge another.

Let $F_{\mathrm{ref}}$ be the authoritative frame transition, $P$ the proposed
state projection, and $K$ the sliced kernel.  For reachable states satisfying
an invariant $\mathcal{I}$, the desired one-step refinement is
\[
  K(P(s),i) = P(F_{\mathrm{ref}}(s,i)).
\]
The complementary noninterference obligation is
\[
  P(s_1)=P(s_2) \Longrightarrow
  P(F_{\mathrm{ref}}(s_1,i))=P(F_{\mathrm{ref}}(s_2,i)),
\]
under $\mathcal{I}$.  This is the formal condition for deleting presentation
state.  Initial-state correspondence, invariant preservation, and terminal
predicate preservation lift the result to an input sequence by induction.  A
future Lean development is intended to mechanize these obligations, while a
separate code-binding argument must connect the theorem to both C++ and the
zkVM guest.

The arithmetic study has two explicit lanes.  The fidelity lane preserves raw
binary32 state and evaluates an integer-implemented IEEE-754 and, where
required, x87 extended-precision baseline with pinned control state, original
instruction selection, store boundaries, conversion helpers, and
transcendental behavior.  Static binary evidence identifies \code{0x027f} as
the control word expected by the CRT trigonometric wrappers: 53-bit significand
precision, round-to-nearest-even, and masked exceptions.  This value is an
explicit execution precondition rather than an assumed loader default.  Intel
documents both the x87 control fields~\cite{intel-fp-reference} and the
approximate, range-reduction-dependent nature of x87 trigonometric
instructions~\cite{intel-x87-transcendentals}; Microsoft documents the exposed
control modes~\cite{microsoft-control87}.

Berkeley SoftFloat Release 3e is used as an independent executable oracle for
the first arithmetic-boundary experiments~\cite{hauser-softfloat3e}.  Its
\code{extF80\_roundingPrecision = 64} setting denotes precision equivalent to
binary64---a 53-bit significand with the extended exponent range---and affects
extended add, subtract, multiply, divide, and square root.  Hardware/SoftFloat
differential tests can reject a candidate semantics quickly.  They cannot
establish that SoftFloat, the assembly harness, or a future formalization is
correct.  The experiment separately maps SoftFloat's five exception flags and
the x87 denormal-operand bit, then tests binary32/binary64 stores,
\code{frndint}, and signed 32/64-bit \code{fistp} under nearest-even and
toward-zero.  Denormal signaling and exception priority follow the Intel and
AMD instruction references~\cite{intel-sdm-vol2a,amd-apm-vol5}, not an assumed
one-to-one SoftFloat mapping.  The comparison extension mirrors the reached
\code{fcomp m32fp}/\code{m64fp} forms and checks C0--C3 plus canonical
ordered, infinity, quiet-NaN, signaling-NaN, and denormal-priority cases.
Transcendental semantics remain outside this oracle.

Helper ABIs are tested separately when the exact body can be isolated without
redistribution.  For \code{\_\_ftol2}, a local tool verifies the retail image,
extracts the pinned address range into a temporary directory, and executes it
in a freestanding i386 stream harness.  An independent integer decoder treats
canonical finite ext80 inputs as exact dyadic rationals and compares the full
EDX:EAX result with truncation toward zero.  This experiment is restricted to
signed-i64-representable inputs.  A bit-mask scan finds 75 full-EAX and two
AL-only observers, but no EDX observer before its bounded branch/call
termination; EDX is still live at 42 such stopping points, so complete
control-flow use remains an obligation.  Range/refinement premises are then
chosen from the actual downstream observation rather than imposed globally.
For a general integer consumer this may require a reachable signed-i32 bound;
for ECL variable resolution it is enough to prove which, if any, of 25
sentinel IDs is selected, including exceptional and out-of-range inputs.

The fidelity representation is address-indexed.  Each retained arithmetic
operation records its pinned original address, x87 stack/control inputs,
opcode, destination width, and next use or store boundary.  Calls such as
\code{\_\_ftol2} and D3DX conversion helpers remain explicit operations.  This
avoids treating source-level C++ expressions as if a different compiler had
reproduced MSVC 7 register allocation and spills.  The target executable hash,
arithmetic-profile version, initial control word, and transcendental-model
identifier are committed by the statement.  This lane may be expensive, but
it provides the semantic oracle and proof-cost baseline.

As an intermediate binding artifact, a canonical JSON ledger records the 244
mapped comparison addresses and 77 mapped \code{\_\_ftol2} call addresses.  It
contains no executable bytes or full operand strings, but binds each address
to the pinned image/mapping hashes, a mapped owner and offset, an evidence
class, and the relevant Lean model contract.  Every slice disposition remains
\code{unclassified}; every helper range remains \code{unproved}.  Thus the
ledger is a quantified work queue for later translation validation and
noninterference proofs, not a premise silently promoted from static analysis.

A second, derived ledger associates every helper address with a manually
reviewed source-expression candidate and semantic sink at a pinned source
revision.  Such an alignment requires consistent function ownership, local
disassembly dataflow, source order, and exact source anchors, but remains
explicitly weaker than debug-line evidence or compiler correctness.  Its
``omit after noninterference'' labels prioritize quotient proofs; they do not
change the conservative base-ledger status.

For the retained ECL call, an observation-specific artifact checks the local
\code{GetVarFloat}/\code{GetVar} instruction signatures and derives its 25-way
jump table.  A finite Lean bit-vector theorem models the decoded wrapping add
and unsigned bound, and an abstract resolver theorem factors all non-sentinel
integer results into the same literal path.  The eventual code-binding theorem
must still validate the decode, helper/classifier semantics, jump-target
meanings, reachability, and guest implementation.

The eight retained point-item calls are handled as a range-proof pipeline.
First, a static artifact verifies the four difficulty blocks, their repeated
binary32 field loads, helper calls, signed threshold, integer constants, and
gameplay-score sink.  Second, a helper artifact checks the 37-instruction
masked-invalid path and isolates its low-EAX observation.  Third, a total
coordinate split handles finite dyadic values, both infinities, and NaN.
Unordered NaN comparisons can produce an apparent collision, so finiteness
cannot be inferred; instead, masked-invalid conversion returns modeled low EAX
zero and selects the top-score branch.  Infinities are separated by a finite
player box, while finite overlap implies a narrow item interval.  A Lean exact-
rational model checks this case split, truncation, and score bounds, while
debug-runner breakpoints search the replay corpus for counterexamples.  Neither
the model theorem nor corpus measurements establish the missing x87,
architectural, reachability, and code bindings.
Reachable difficulty $0..4$ and the pre-item global-score cap are recorded as
separate control invariants rather than assumed from the selected profile.

The optimization lane uses field-specific fixed-point formats, explicit
overflow and rounding, integer phase angles, and deterministic trigonometric
tables or polynomials.

A fixed-point guest may be called compatible with the shipped executable only
after a formal refinement argument covers every reachable transition in the
claimed domain.  Replay and generated boundary tests remain necessary for
finding counterexamples, but finite tests alone establish neither universal
arithmetic equivalence nor soundness.  If a refinement proof is unavailable,
the project must either retain the exact arithmetic path or state a distinct
integer-kernel claim.
