\section{Conclusion}

\project{} treats semantic equivalence as the first-class obstacle to proving
a legacy game's execution.  The initial replay runner demonstrates that the
reconstructed engine can consume real v1.02h witnesses deterministically and
complete full runs, while strict parsing removes several ambient-memory and
format-trust hazards.  The result is not yet a proof system and is not yet an
exact model of the shipped executable.

An experimental shared binary protocol now emits real per-frame subsystem and
root digests with raw floating-point bits, stable identities, and fail-closed
decoding.  Complete repeated Linux runs are byte-identical, and the first broad
ANM experiment already exposed the distinction between allocated memory and
future-live semantic state.  The next concrete milestone is to resolve the
known reuse and dynamic-job omissions, add selected field-level snapshots, and
emit the same schema from the shipped or an exact-reference executable.  This
should turn ``the replay desynchronized'' into a reproducible first-frame,
first-subsystem, first-field diagnosis.

A first static arithmetic census now makes the floating-point gate concrete:
the mapped game surface contains thousands of x87 operations, 26 inline
\code{fsincos} sites, 1,793 stores, and numerous calls into conversion and
transcendental helpers.  The embedded \code{0x027f} control profile is decoded
in Lean together with the D3DX toward-zero profile.  A pinned SoftFloat probe
matches 34,002,802 hardware result/condition/exception tuples across basic
arithmetic, stores, rounding, integer conversion, and both reached comparison
widths, after an initial denormal-priority rule was falsified and corrected.
All 244 mapped comparison consumers are classified into eleven checked truth
tables.  A temporary i386 harness additionally matches 1,000,014 in-domain
executions of the exact \code{\_\_ftol2} body against dyadic truncation, plus
1,000,154 focused executions against its ECL sentinel observation.  This
surface is indexed by a hash-bound ledger of 244 comparison and 77 helper
addresses.  A bit-mask re-audit records 75 full-EAX and two AL-only helper
observers, while a derived source ledger proposes 68 omission and nine retain
candidates.  For the ECL call, a pinned 25-way dispatch audit and Lean theorem
replace a blanket range goal with exact helper-to-classifier refinement.  This
same observation-driven analysis binds the eight point-item calls to four
score profiles and exposes why collision success cannot prove finiteness in
the presence of NaN.  A 37-instruction helper audit and Lean low-EAX theorem
instead support a total finite/infinity/NaN score model: exceptional invalid
conversion selects the bounded top branch, while finite collection gives the
geometric interval.  The model conditionally proves the resulting score
bounds; 2,081 Linux collections supply counterexample-search evidence for its
finite branch.  This remains conservative bookkeeping: startup state,
load/remainder behavior, noninterference, the finite bounded player invariant,
architectural helper semantics, verified code correspondence, and
transcendental microarchitecture are not yet proved.  The
fidelity design therefore binds operations to original addresses and actual
observations instead of assuming source-level host arithmetic is exact.

That evidence will guide the projection, but it cannot prove a slice sound.
The intended end state additionally requires a machine-checked commuting
transition and noninterference argument, exact or refined arithmetic semantics,
and a reviewed binding from those definitions to both executables.  Only then
can zkVM performance results support the intended claim.
