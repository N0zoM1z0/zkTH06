\subsection{Shipped-executable differential anchor}

The first retail experiment runs the pinned Japanese v1.02h executable under
Wine 11.0 and the tracked Normal Reimu A NN/NB replay.  A debugger verifies the
expected bytes at the menu, input, and frame-anchor addresses and samples at
\code{0x00420858}, immediately after \code{Chain::RunCalcChain}.  The Linux
runner writes its diagnostic row at the corresponding return boundary.  The
comparison first covered 34 fields: route/frame metadata, complete replay input, RNG
seed and generation, score/resources/rank, Player state and raw binary32 x/y/z
bits, time-stop state, raw effective-rate bits, movement-area bounds, bomb
movement multipliers, and all four character movement speeds.
The enclosing-state extension adds configured framerate multiplier, respawn
timer, active-bomb state, and all three invulnerability-timer words, for 40
fields total.  The shooting extension adds the GUI current-message predicate,
focus and previous-input state, and all three fire-timer words, for 46 fields.
The local bullet-spawn extension adds a structured entry/exit projection as a
47th field on callback-bearing frames.
The lifecycle extension adds update before/after, last-hit target, and
post-frame pool fields for a 50-field projection.  Retail drawing causes 3,898
raw differences only in collided-bullet sprite z.  These values are excluded
explicitly because the next update overwrites all sprite coordinates from
gameplay position before bounds or ANM reads them.

All 2,000 compared frames match.  This interval contains 27 distinct input
masks, advances RNG generation from 2 to 3,555, and reaches score 767,990.
Every retail anchor observes x87 control word \code{0x007f} and MXCSR
\code{0x00001fa0}.  The raw trace hashes, executable and replay identities,
environment versions, and compared-field list are sealed in the
proprietary-byte-free evidence artifact
\path{evidence/retail-reference-002677-2000-v1.json}.

The Wine environment requires two explicit diagnostic interventions.  Its
\code{timeGetTime} begins near host uptime while the game's last-frame global
begins at zero, so the probe equates those values before gameplay to avoid a
spurious multi-year catch-up loop.  XTest does not reach Wine DirectInput on
this host, so the physical input routine returns zero; ReplayManager then
overwrites the complete replay mask at its authentic calc priority.  The
per-frame input equality is checked rather than assumed.  These interventions
and the finite 50-field semantic projection prevent promoting the result to whole-state
or whole-program equivalence, but they establish a real retail oracle for the
first core slice.

\subsection{Player-position sliced-kernel gate}

The extended anchor exposes every value consumed by the position arithmetic.
From its 2,000 post-calc rows, the first row supplies an initial observed
position and the remaining rows define 1,999 consecutive transitions.  A
compact fixed-width vector retains each input mask, time/player gate, raw
movement environment, previous x/y bits, and expected next x/y bits while
binding the target, replay, and retail-trace hashes in its header.

The integer PC24 microkernel matches all 1,999 transitions exactly.  Separate
unit tests exercise direction priority, focus speeds, clamps, signed zero,
ties-to-even, unsupported classes, and time-stop ordering.  A deterministic
50,000-pair normal-domain comparison also agrees with host binary32 add,
multiply, and ordering; host floating point is used only as a test oracle, not
by the kernel.  These results validate the reached implementation path but do
not prove the integer rounding algorithm, per-instruction control state,
instruction/source correspondence, reachable-domain invariant, or projection
noninterference.

\subsection{Canonical projection experiment}

Two independent complete revision-0.2 traces of the Normal Reimu A NN/NB run
were byte-identical across all 85,759 frame records.  Both terminated at Stage
6 frame 17,283 with score 172,519,700.  Each trace occupied 50,769,392 bytes and
had SHA-256
\begin{center}
\small\ttfamily
ea0cdf948ba7668cba31064dfa421a9c279fdab28bdbd1d57c817ba13db84117.
\end{center}
Although only fixed-size digests were retained, each run hashed
6,192,210,130 bytes (5.767 GiB) of selected canonical payload.  Two concurrent
local executions took 31.90 and 32.04 seconds and peaked at 38,388 and 38,724
KiB resident memory.  This measures the current diagnostic implementation; it
does not estimate zkVM proving cost.

An earlier serializer hashed every named member of each Stage ANM VM.  Two
2,000-tick runs then disagreed in the Stage subsystem at record zero, while RNG
and all other subsystem digests agreed.  Inspection showed that Stage VMs are
allocated with \code{malloc} and that disabled interpolation members are not
initialized.  Encoding those members only when their control mode can read
them restored byte identity for both the 2,000-tick and complete runs.  This is
a concrete example of why a canonical state must follow future-read semantics
rather than C++ object layout.

The complementary inactive-state failure is machine-checked in a small Lean
model.  Two free Effect slots with equal active-only projections but distinct
raw radius bits evolve to distinct projected states under the same spell-orbit
allocation.  A second theorem shows that retaining dormant radius and angle
makes this modeled allocation phase commute.  The proof compiles with Lean
4.32.0 without \code{sorry}, admitted results, or custom axioms.  Its scope is
only this allocation phase and does not establish sufficiency for all Effect
callbacks or bind the model to compiled C++.

\subsection{Extracted \code{\_\_ftol2} experiment}

The helper occupies 117 bytes at virtual address \code{0x0045ba78}; the local
extractor binds its body by SHA-256 after first verifying the complete retail
image.  It retains the bytes only in a temporary directory and links them into
a freestanding i386 stream harness, so neither the executable fragment nor a
derived object is redistributed.

An independent Python decoder computes truncation toward zero directly from
the sign, exponent, and significand of canonical finite ext80 values.  On the
same host, 1,000,014 fixed and deterministic PC53 inputs in the signed-i64
domain produced identical complete EDX:EAX values; every invocation returned
the x87 stack to empty, and 908,273 cases left the inexact flag set.  The run
took 3.5 seconds.  A Lean case model separately checks the helper's
nearest-even carry/borrow correction and the EDX:EAX split/join identity.

A second campaign queried only the observation used by ECL variable dispatch.
Its 1,000,154 cases include quarter-step boundaries around IDs $-10025$ through
$-10001$, dense deterministic PC53 samples, infinities, quiet/signaling NaNs,
large finite values, a pseudo-denormal, and an unnormal.  All classifications
matched; 3,084 operands selected a variable ID and nine cases set invalid.
All nine invalid cases returned the complete integer-indefinite result
\code{0x8000000000000000}.  The combined campaign therefore executed the exact
helper 2,000,168 times.

The signed-i64 truncation result is deliberately claimed only for its tested
canonical finite domain.  The nine sampled invalid results and the classifier
campaign are finite counterexample search, not universal exceptional
semantics.  A separate byte-free artifact checks all 37 helper instruction
signatures and records the masked-invalid path; a Lean bit-vector theorem
checks that integer-indefinite projects to EAX zero and EDX
\code{0x80000000}.  Those results remain conditional on verified decoding,
architectural x87 semantics, entry stack/control state, branch binding, caller
binding, and guest refinement.  General integer consumers still require their
site-specific range or observation invariants.  The ECL call instead requires
exact agreement on the 25 sentinel outcomes before the helper can be replaced
by a smaller classifier in the proof kernel.

\subsection{Fixed-data ECL alias-writer audit}

The ECL variable resolver returns pointers for the player-position IDs and
marks them readonly.  Most output handlers honor this type, but retail opcodes
18 and 19 increment or decrement the returned pointer directly.  Consequently,
a source search for explicit player assignments is not a complete writer
inventory: a fixed script could name player y as an aliased output.

The new artifact binds the executable, mapping, data manifest, stage archive,
and variable-dispatch audit.  A pinned thtk Release 12 extraction~\cite{thtk}
is checked by the hashes of all seven ECL outputs.  An independent parser then
walks 321 subroutines, their 321 sentinels, and 8,384 instructions.  It
identifies 1,844 candidate output operations; none names a readonly or
player-position ID.  Of
these, 80 are direct increment/decrement operations that bypass the type guard.
Their destination support is only four local IDs: $-10012$, $-10004$,
$-10002$, and $-10001$.  The artifact also checks 28 retail instruction
signatures and 17 source anchors.  A Lean policy theorem reduces a modeled
player-y alias write to one of the unchecked opcodes and checks the transcribed
four-ID support.

This result is conditional.  The thdat extraction is not proved equivalent to
the retail PBG3 loader; the independent walk is not yet connected to the
runtime decoder; handler classification, compiler correspondence, instruction
immutability, non-ECL alias completeness, artifact-to-Lean binding, and guest
refinement remain open.  It nevertheless removes a concrete fixed-data
counterexample family without assuming that the readonly guard is universally
obeyed.

\subsection{Player-position clamp decomposition}

A dependent artifact checks 95 exact instruction signatures across eight
mapped functions, 21 source anchors at the pinned authoritative revision, five
binary32 constants, four character-speed records, and four comparison sites
from the base ledger.  It covers initialization and respawn at center
$y=384$, movement-speed construction, bomb and effective-frame multipliers,
the ordered clamp to $[16,432]$, radius-12 grab-box construction, and the
vertical item-collision branches.  The point-item artifact seals this player
artifact's digest as a direct input, and the player artifact in turn seals the
fixed-data ECL writer artifact.

The exceptional cases make the invariant smaller than expected.  Negative
infinity satisfies the lower comparison and is assigned 16; positive infinity
satisfies the upper comparison and is assigned 432.  NaN makes each comparison
unordered and takes the two audited parity branches that skip assignment.  A
total Lean theorem therefore proves that the clamp yields a finite bounded
center for every candidate except NaN.  Further theorems check initial and
respawn boundedness and derive grab-top and grab-bottom ranges $[4,420]$ and
$[28,444]$.

This does not yet prove the reachable player invariant.  The remaining queue
contains verified decode and source correspondence, GameManager
reinitialization, the ECL extraction/parser/handler bindings, non-ECL direct
and aliased writer coverage, finite movement operands and non-NaN candidate
construction, binary32 store and x87 comparison semantics, Player-before-Item
scheduling, and guest refinement.  In particular, the audit records adaptive
effective-frame-multiplier publishers and does not replace them with a
constant-one assumption.

\subsection{Point-item range decomposition}

The eight scoring calls are grouped into four difficulty profiles.  A pinned
binary artifact checks 77 key instruction signatures: the five-entry
difficulty dispatch, two binary32 loads of the same
\code{Item.currentPosition.y} field per profile, both helper calls, signed
threshold 128, profile constants, 32-bit penalty arithmetic, joins, and the
final gameplay-score addition.  This is static decode evidence, not verified
translation.

The apparent range argument contains a NaN trap.  The collision function
returns false when any ordered comparison proves the player and item boxes
separate.  If an item coordinate is NaN, each such comparison is false and the
function can instead return collision success.  Therefore collection alone is
not a finiteness witness.  Rather than assume item finiteness, the total model
splits its binary32 coordinate into exact finite rationals, both infinities,
and NaN.  With finite player center $y\in[16,432]$, player grab radius 12, and
item half-size 8, a collected finite item lies in $[-4,452]$ and truncation
toward zero preserves that interval.  Either infinity is vertically separated
from the finite player box.  NaN may fall through to collision success, but
masked-invalid \code{fistp} produces integer-indefinite; the audited scoring
callers observe EAX zero and select the top-score branch.  Across this total
case split the Lean theorem bounds all four score formulas by
$[27600,300000]$; their largest finite position penalty is 129600 and every
selected score fits signed i32.  Given a pre-item score at most 999,999,999, a
further theorem rules out u32 wrap in one award.  This theorem is conditional
on discharge of the player-position artifact and exact collision/helper
observations.
