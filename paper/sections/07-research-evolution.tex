\section{Evolution of the Research Direction}

This section is intentionally chronological.  Superseded ideas remain visible
so that later design choices can be audited rather than reconstructed from
memory.

\paragraph{Phase A: prove the ECL virtual machine.}
The initial idea treated enemy ECL as the natural zkVM target.  ECL has an
explicit instruction format, registers, comparison state, call stack, program
counter, and interpreter loop, making it attractive for an opcode-constraint
prototype.

\paragraph{Phase B: recognize the open environment.}
Source inspection showed that ECL reads Player and GameManager state, shares the
global RNG, and mutates bullets, items, GUI, and scoring state.  A proof of ECL
alone could accept forged player positions or rank.  The claim was narrowed
from ``a TH06 pattern was executed'' to ``ECL executed under supplied external
inputs,'' which was judged insufficient as the main result.

\paragraph{Phase C: reframe the game as a frame transition.}
The project moved from inventing a larger VM to extracting a deterministic
gameplay kernel $S_{t+1}=F(S_t,I_t)$.  ECL became one ordered subsystem.  This
reframing also made replay inputs a natural witness serialization.

\paragraph{Phase D: distrust replay checkpoints.}
Inspection of ReplayManager revealed that each stage carries mutable resources
and RNG state that playback restores directly.  Merely proving successful
playback would allow forged resources at every boundary.  Canonical proof mode
must derive stage continuity and constrain or discard those snapshots.

\paragraph{Phase E: differential validation before ZK.}
The portable headless runner was found deterministic but not known equivalent:
it substitutes host math for x87 behavior and skips draw callbacks that can
write later-observable state.  The immediate milestone changed from circuit
construction to an exact replay differential runner against the shipped or an
exactly matched reference executable.

\paragraph{Phase F: digest first, snapshot on divergence.}
A naive full-state dump for 640 enemy bullets, 513 items, effects, enemies, and
ANM state on every frame is unnecessarily large.  The current design emits
ordered subsystem digests each frame, then reruns only the first mismatching
tick with a versioned field-level snapshot.  Stable slot identity and iteration
order are retained because allocation, collision, and RNG behavior can depend
on them.

\paragraph{Phase G: separate arithmetic fidelity from proof optimization.}
Raw floating-point bits can reveal a mismatch but do not make floating-point
execution cheap in a zkVM.  The arithmetic plan was therefore split into an
exact, integer-implemented floating-point baseline and a fixed-point candidate.
The exact lane protects the original-semantics claim and measures its real
cost.  The fixed-point lane is an optimization only if a refinement argument
preserves every claimed transition; corpus agreement alone cannot supply that
argument.  Otherwise it defines a different, explicitly named game kernel.

\paragraph{Phase H: make slicing a refinement theorem.}
Removing presentation state because sampled replays still finish was judged an
insufficient basis for a sound proof.  The kernel boundary is now required to
support a commuting one-frame diagram and a noninterference theorem for omitted
state, followed by induction over the input stream.  Lean is the intended
proof environment, but the theorem must also be bound to the actual C++
reference and zkVM guest; a proof of an unconnected handwritten model would not
close the claim.

\paragraph{Phase I: distinguish allocated memory from future-live state.}
The first real ANM projection was intentionally broad and immediately produced
a false Stage divergence from uninitialized, disabled interpolation members.
Guarding those members by the mode that can read them restored deterministic
traces.  The same audit then exposed the converse error: inactive Effect slots
retain motion values that can affect a later allocation, so active-only hashing
is too narrow.  The state boundary is now developed as an explicit queue of
owner-local overwrite-before-read and noninterference lemmas.

\paragraph{Phase J: bind arithmetic to original addresses.}
A source-level plan of ``use software IEEE-754 and x87 where required'' was too
coarse.  Static analysis found 5,980 x87 instructions in mapped game functions,
26 inline \code{fsincos} sites, 1,793 explicit stores, and 163 direct calls to
x87 helpers or wrappers.  It also found XMM-bearing CRT/D3DX code outside the
game-function ranges.  The fidelity lane therefore changed to an
address-indexed arithmetic IR whose operations retain original opcode, control
state, and store width.  Control word \code{0x027f} is now an explicit checked
profile, while its loader-established entry value and the processor-dependent
transcendental model remain open evidence obligations.

\paragraph{Phase K: test a basic-operation oracle without promoting it to a proof.}
The decoded 53-bit x87 profile suggested Berkeley SoftFloat's reduced-precision
extended operations as a candidate exact baseline.  A pinned differential
probe found no result-bit mismatch across more than ten million basic-operation
cases spanning binary32 inputs and the extended exponent range.  This narrowed
implementation risk, but also sharpened the claim boundary: SoftFloat is not a
formal proof, does not model x87 transcendental instructions, and does not by
itself bind arithmetic semantics to original instruction addresses.  The next
arithmetic milestone therefore became stores, conversions, status behavior,
and code-to-model binding rather than immediate fixed-point substitution.

\paragraph{Phase L: make exception priority part of the operation semantics.}
Extending the oracle to all six x87 exception bits immediately falsified the
first denormal rule: a subnormal dividend divided by zero set zero-divide but
not denormal-operand for the isolated arithmetic instruction.  Instruction
references also distinguish \code{frndint}, which can set denormal-operand,
from \code{fistp} and \code{fstp}, which do not.  The probe now treats this bit
as opcode- and priority-specific, tests five store/round/conversion boundaries
under nearest-even and toward-zero, and records exception-coverage counts.  The
result strengthened the executable oracle while reinforcing that floating
point must be modeled as an instruction/state machine rather than as pure real
arithmetic plus a single rounding function.

\paragraph{Phase M: preserve machine comparisons and narrow helper claims by
proved domains.}
The next audit found that all 244 mapped comparisons use memory-operand
\code{fcomp} followed by one of eleven concrete status-mask/branch sequences.
Replacing them with a host-language comparison would erase the unordered path,
so the design now retains the C0/C2/C3 relation and the actual consumer mask.
The SoftFloat probe was extended through both reached memory widths and fixed
NaN/denormal priority cases.  In parallel, executing the exact 117-byte
\code{\_\_ftol2} body showed truncation agreement throughout a canonical
signed-i64 test domain, while the call audit showed gameplay observes only
EAX/AL.  This did not license a global cast replacement: it instead exposed a
new invariant obligation that every reachable caller input lies in signed i32.
Thus simplification is admitted by a range theorem, not by the apparent intent
of the reconstructed cast or by passing samples.

\paragraph{Phase N: turn aggregate evidence into conservative per-address
obligations.}
The first helper-use summary stored only whether some EAX-family token appeared
in a bounded suffix and consequently described one consumer as AL-only.  A
bit-mask-level re-audit found two: one in Stage update and one in the bullet
added callback; the other 75 consume full EAX.  It also exposed that EDX is
still live at 42 branch/call stopping points.  The design therefore no longer
uses the bounded scan as a dead-result claim.  A hash-bound ledger now records
all 321 comparison/helper addresses, tool and input identities, exact local
observation masks, and explicitly open slice/range fields.  This changed the
next milestone from ``bind addresses'' in the abstract to discharging each
address with either a retained-operation refinement or an omitted-path
noninterference theorem.

\paragraph{Phase O: quotient conversions by their actual observation.}
Manually aligning all 77 helper addresses with pinned source anchors split the
queue into 68 presentation/audio omission candidates and nine retained calls.
The first retained call initially appeared to require the same global signed-
i32 range theorem as the eight point-item score conversions.  Inspecting its
consumer changed that target: \code{GetVarFloat} uses the low result only to
select one of 25 contiguous ECL variable labels, and returns the original float
for every other integer.  A pinned jump-table audit and a Lean bit-vector
theorem now isolate this observation quotient.  The desired theorem is exact
helper-to-classifier agreement for every reachable raw operand, including the
default behavior of exceptional inputs, rather than equality of an otherwise
unobserved conversion result.  This reduces constraint and proof surface
without weakening soundness; static alignment and finite differential tests
remain evidence, not the missing universal code-binding theorem.

\paragraph{Phase P: split geometric range arguments at unordered values.}
The remaining eight retained conversions all compute point-item score from the
same binary32 $y$ field.  Their collision precondition initially seemed to
give the desired range immediately: a collected item should be close to the
bounded player.  Inspecting the actual separation test exposed a soundness
hole---NaN makes each ordered comparison false and can therefore fall through
to collision success.  The proof target was split into a finite/non-NaN
reachability invariant, an ordered AABB geometry lemma, exact helper
refinement, and bounded integer score arithmetic.  The binary score blocks and
constants are now address-bound, while Lean checks the latter two mathematical
steps conditional on integer inputs.  A four-replay debug probe found 2,081
finite collected values inside the proposed interval and no counterexample;
this guides the invariant but deliberately does not promote corpus absence of
NaN into a universal premise.  This phase exposed the problem but its initial
finite-item premise is superseded by the next phase.

\paragraph{Phase Q: quotient exceptional score inputs by the caller's view.}
Auditing all 37 helper instructions exposed a smaller total proof than the
finite-item reachability goal.  With masked invalid conversion, NaN produces
integer-indefinite \code{0x8000000000000000}; every retained scoring caller
observes its zero low EAX half.  The helper's correction path is bypassed, and
zero selects the bounded top-score branch.  At the same time, either infinity
is separated by the ordered vertical comparisons against a finite player box,
whereas a finite overlapping value admits the exact rational interval proof.
The Lean model now performs this finite/infinity/NaN case split and no longer
assumes item finiteness.  This change preserves the exceptional behavior
rather than excluding it.  It shifts the remaining universal obligations to a
finite bounded player-box invariant and exact bindings for binary32 load and
x87 comparison semantics, masked-invalid helper control flow, each scoring
caller, and the zkVM guest.

\paragraph{Phase R: totalize the player clamp before proving reachability.}
The remaining ``finite bounded player'' premise was still too coarse to audit
soundly.  Reading the retail branch sequence showed that the clamp itself
repairs more states than a finite-only model admits: negative infinity takes
the lower assignment, positive infinity takes the upper assignment, and only
NaN follows the two unordered parity branches that preserve the candidate.
A 95-instruction artifact now follows initial/respawn writes, movement speeds,
bomb and effective-frame multipliers, both clamp comparisons, grab-box
construction, and its collision consumer.  A total Lean theorem correspondingly
reduces invariant preservation to excluding a NaN movement candidate, while
separate lemmas check the initial and respawn bases and grab-box bounds.  The
point-item artifact seals this new artifact as an input.  This does not assume
the invariant solved: complete direct and aliased writers, GameManager
reinitialization, non-NaN arithmetic, Player-before-Item scheduling, verified
decode/source correspondence, x87/binary32 semantics, and guest refinement
remain the explicit proof queue.

\paragraph{Phase S: treat script-resolved pointers as writers.}
A direct source search suggested that only initialization, respawn, movement,
and one bomb callback wrote the player center or its multipliers.  Inspecting
the ECL resolver invalidated that inventory: player coordinates are exposed as
readonly variable pointers, and opcodes 18/19 increment or decrement a resolved
pointer without checking its reported type.  We therefore moved fixed script
data into the invariant argument.  A hash-bound audit extracts all seven retail
ECL files, independently walks 8,384 subroutine instructions, and checks 1,844
candidate output operands.  It finds no player-position destination; all 80
guard-bypassing writes target four local-variable IDs.  A small Lean policy
model records why only those unchecked handlers matter.  This removes neither
the archive/runtime-decoder correspondence nor whole-program alias obligations:
extraction, parsing, handler exhaustiveness, immutability, compiler binding,
non-ECL writes, and guest refinement remain explicit.  The methodological
change is durable: future writer inventories must include data-driven pointer
resolution, not only syntactic assignments.

\paragraph{Phase T: establish a retail anchor before enlarging the slice.}
Running the shipped executable under Wine exposed two harness effects before it
exposed a gameplay mismatch: the host-uptime interpretation of
\code{timeGetTime} caused a pre-game catch-up loop, and XTest events did not
reach DirectInput.  Both interventions were moved into a hash- and
address-checked probe, restricted to pre-game timing normalization and zero
physical input that ReplayManager overwrites.  The first 2,000 post-calc frames
then matched the Linux reference on a 34-field raw projection, including Player
binary32 bits and RNG evolution.  This result changes the project gate from
``no original execution evidence'' to ``a narrow retail anchor exists.''  It
licenses work on the first sliced-kernel boundary while keeping full canonical
subsystem export, replay diversity, noninterference, and formal code binding
open.  The same run also observed ambient control word \code{0x007f} at every
anchor, falsifying the working idea that the CRT's embedded \code{0x027f} could
serve as one global gameplay profile.

\paragraph{Phase U: freeze one fail-closed arithmetic slice before a full
guest.}
The enlarged anchor made the Player position transition self-contained: replay
input, callback gates, bounds, multipliers, movement speeds, and expected raw
positions were all observed on both executions.  Instead of waiting for a
whole-game projection or using native Rust \code{f32}, the first microkernel
implements only this transition with integer dyadics and explicit PC24
rounding.  It matches 1,999 consecutive retail-derived transitions and rejects
unsupported arithmetic classes or callback states.  This changes the route
again: zkVM cost and code-binding work can start on a real executable slice,
while formal arithmetic correctness, noninterference, broader replays, and the
complete guest remain open rather than being implied by the finite match.

\paragraph{Phase V: reject an uncommitted witness and bind the first real
backend statement.}
The initial OpenVM adapter published initial position, final position, and
transition count.  Although its application proof verified and was bound to
the intended executable, the environment transcript was private and
uncommitted; the actual statement was only that some 1,999-step witness reached
the endpoint.  Before freezing evidence, the adapter was changed to hash a
domain separator, every validated workload byte, and the guest-computed final
position, exposing the full SHA-256 digest as its public value.  Direct proof
deserialization confirms that the authenticated bytes equal the independently
computed digest.  The stronger statement raises the full-prefix meter result
from 230,560,805 to 254,156,116 cells, a 10.2339\% overhead.  This change keeps
the research route soundness-first: the first backend milestone is now a real,
reproducible OpenVM proof of a fixed sliced workload/result, while derivation of
the movement environment from complete gameplay state becomes the explicit
next boundary rather than hidden witness trust.

\paragraph{Phase W: replace environment records with an enclosing state.}
Hashing the environment transcript prevented post-hoc substitution but did not
make its contents consequences of TH06 state: a prover could still choose any
internally valid sequence of eleven rate/bounds/multiplier/speed/gate words and
commit it.  The next transition therefore fixes a versioned post-calc anchor,
carries Player life state, invulnerability timer, time-stop and bomb flags, and
derives the motion environment from the preceding state plus one character/shot
configuration.  Unsupported bomb input/active callbacks, hit/death paths,
external time-stop writers, and non-full-speed timers fail closed.  The new
private record is only a 16-bit replay mask.  A 40-field retail/reference trace
matches for 2,000 anchors, a compact vector checks all 1,999 state transitions,
and a 55-instruction/30-source-anchor artifact makes the selected retail
ordering reviewable.  The OpenVM proof reduces payload size from 95,976 to
4,018 bytes and cells from 254,156,116 to 209,865,030 while authenticating a
stronger final state.  This closes the immediate witness boundary without
overstating the result: deriving the anchor from registration and proving
complete writer exclusion/refinement are now the next explicit obligations.

\paragraph{Phase X: refine shooting at a callback boundary, not as one opaque
subsystem.}
``Add shooting'' initially appears to require bullets, callbacks, collision,
power, and bombs at once.  Source and disassembly order instead expose a
smaller closed step: input derives focus and previous input, the dialogue gate
may start an inactive timer at zero, and the timer emits one
\code{SpawnBullets(player,timer)} request before its full-speed tick and reset.
We froze this call boundary first.  A 46-field retail/reference trace matches
for 2,000 anchors, while a derived vector checks 1,999 transitions and 1,590
callback arguments.  The new OpenVM guest retains the 4,018-byte replay-only
payload and costs 211,737,944 cells, only 0.8924\% above the enclosing-state
guest.  This converts ``shooting support'' from an underspecified claim into a
reviewable refinement ladder: cadence is now proven for the selected profile;
bullet-slot allocation and each fixed character/shot callback became the next
separate obligations addressed by Phase Y.  The no-dialogue corpus fact
remains finite evidence,
not a universal noninterference theorem.

\paragraph{Phase Y: prove local allocation before claiming cross-frame bullet
state.}
Entering the callback exposed two different goals that should not be conflated.
The first is a closed local function: given all 80 slot states, select Reimu-A
rank/timer rows, scan the lowest unused slots, and initialize geometry.  The
second is an enclosing transition that must itself derive those slot states
through bullet motion, collision, ANM termination, and reclamation.  We prove
the first goal over 1,590 retail-bound calls and 422 outputs, but keep each
pre-state independently observed.  The fourth OpenVM guest costs 309,751,316
cells and its public digest covers every initialized bullet.  This prevents a
per-frame oracle from being mislabeled as persistent bullet state and leaves a
precise next proof obligation: compose the local allocator with all writers of
slot liveness.

\paragraph{Phase Z: close only the writer-local prefix, then stop.}
Tracing the full update order showed that a useful enclosing transition did
not require solving all Enemy and ECL semantics at once.  From the fixed empty
frame-1 pool, rank-1 type-0 bullet motion, sprite synchronization, bounds
reclamation, fixed ANM/timer behavior, and allocation are owner-local until
EnemyManager first writes collided state at frame 208.  We therefore close 206
transitions and reject the next step.  The private payload falls from 197,180
bytes of independently observed callback records to 436 bytes of replay masks,
while the public digest covers every intermediate state.  The fifth guest costs
474,516,189 cells.  This is the intended soundness pattern for future growth:
derive state while the writer inventory is closed, and make the first omitted
writer an enforced boundary rather than an unspoken assumption.  The next
obligation is now concrete Enemy/ECL collision composition, not generic
``bullet support.''

\paragraph{Phase AA: compose the stopping writer without importing it as a
witness.}
The frame-208 boundary could have been crossed by supplying observed Enemy
positions or collision results, but that would recreate the witness-trust
problem eliminated in Phase Z.  Instead, a new enclosing state derives five
fixed Stage-1 timeline spawns and their manager-ordered movement, in-bounds and
ECL transitions before executing damage, target, death, and score updates.  A
225-frame dual-oracle trace exposes every damage call and a raw Enemy/ECL
projection; the selected 207-transition vector contains 200 calls and the
unique first hit.  The sixth OpenVM proof adds only one replay mask---two bytes
of private payload---while its public digest binds the derived Enemy
projection and collision metrics.  The resulting 769,444,525-cell proof
demonstrates the intended expansion rule: new subsystem state must be a
consequence of the preceding closed state, fixed resources, and replay input.
The finite x87 curve table and omitted Sub0 shooting path are recorded as
refinement and noninterference obligations rather than silently promoted to
equivalence claims.

Future changes to the central claim or state boundary should be appended here
with the evidence that motivated them.
